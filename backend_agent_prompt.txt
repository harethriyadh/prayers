Required API endpoints and behavior

1) GET /api/prayers
- Description: Return all stored prayer data.
- Response 200 JSON shape: {
    "2025-11-24": { "الفجر": 1, "الظهر": 3, ... },
    "2025-11-23": { ... }
  }

2) GET /api/prayers/:dateKey
- Description: Return prayer statuses for a single date key (YYYY-MM-DD).
- Response 200 JSON shape: { "الفجر": 1, "الظهر": 2, ... }
- If no data for date, return 200 with an empty object {}.

3) POST /api/prayers
- Description: Upsert a single prayer status for a given date.
- Request JSON body: { "date": "YYYY-MM-DD", "prayer": "الفجر", "status": 1 }
- Validations: date must match YYYY-MM-DD, prayer must be non-empty string, status must be integer (1,2,3).
- Response 200 JSON: { success: true, data: { <the updated day object> } }

4) POST /api/prayers/batch
- Description: Retrieve multiple dates in one call. Useful for the History page.
- Request JSON body: { "dates": ["YYYY-MM-DD", "YYYY-MM-DD"] }
- Response 200 JSON shape: { "YYYY-MM-DD": { ... }, "YYYY-MM-DD": { ... } }
- If date not present, respond with empty object for that key.

5) (Optional) DELETE /api/prayers/:dateKey
- For convenience during testing, provide an endpoint to delete a day's data. This is optional but helpful for tests & e2e.

Data model

- Save data as an object keyed by date (YYYY-MM-DD) with values mapping prayer names to status integer.
- Example storage row for SQLite: table `prayer_days` with columns: date TEXT PRIMARY KEY, data JSON
- When updating a single prayer status via POST /api/prayers, merge the new value into the existing day's object.

Non-functional requirements

- Node.js >= 18.
- Use Express.js for the HTTP server.
- Use better-sqlite3 or sqlite3 for SQLite; if SQLite is not possible, use lowdb with atomic write options.
- Validate inputs with a library (zod or joi) or lightweight manual checks, and return meaningful 4xx errors on bad input.
- Add CORS enabling, body size limit (e.g., 10kb or so), and basic request logging (morgan or simple console logs).
- Graceful error handling middleware that returns JSON { error: "message" } with appropriate status codes.
- No secrets or sensitive data should be written to the repo.
